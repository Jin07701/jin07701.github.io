## Phase 1 で実装したもの

- 全テーブルのスキーマ (`supabase/migrations/0001_init.sql`)
- 駐輪場・区画・料金ルールの投入 (`npm run db:seed`、§37 のデモ3拠点)
- 区画ごとの推測困難なQRトークンと、その場でのPNG生成 (`/api/qr/[token]`)
- QR着地ページ (`/s/[token]`) — 場所・区画・料金・利用ボタンのみ
- 利用中ページ (`/session/[id]`) — 開始時刻・経過・現在料金
- 完了ページ (`/session/[id]/done`) — サーバー確定額
- サーバー側の料金計算(24時間上限つき)
- 同一区画の二重利用を DB の部分ユニークインデックスで排除
- トラブル報告の受付 (`/report/[token]`、写真なし)
- 駐輪場一覧 (`/`) と区画・QR一覧 (`/l/[id]`)

## Phase 5 のうち先行して入れたもの

- `incident_reports` テーブルと、利用者からの報告受付
- 報告があっても区画の状態を自動では変えない運用(§15)

写真添付は Supabase Storage の導入が前提のため未実装。
出庫忘れの通知(§14)は、`parking_sessions.last_reminder_at` / `reminder_count` と
長時間利用を拾うインデックスまで用意し、通知の送信処理自体はこれから。

## 次にやること (Phase 2)

1. `users` に電話番号/メール認証を追加し、Cookie だけの識別から移行する
2. Stripe Customer と PaymentMethod の登録を初回利用に組み込む
3. 利用終了を `PAYMENT_PENDING` 経由にし、`payments` に冪等キー付きで記録する
4. Stripe Webhook を正として `COMPLETED` / 失敗へ遷移させる (§34)
5. §38 ケース5(決済失敗からの再決済)をE2Eに追加する

QR着地ページの表示イベントも記録する必要がある。これは Phase 2 で追加する。
