# 運用組織

## 目的

成果物を GitHub Pages 上で公開し、公開後の状態を維持する。

## 責務

- 公開手順を定め、実行する
- 公開範囲を確認する（このリポジトリは公開サイトのため、追加ファイルは原則すべて公開される）
- 外部サービス側の設定と整合しているかを確認する（例: AdSense 管理画面と `app-ads.txt` の内容）
- ブランチ運用を管理する（作業ブランチ → 既定ブランチへの反映）
- 公開後に影響が出た場合の切り戻し手順を用意する

## 担当範囲

**含む**

- 公開手順の策定と実行
- 公開範囲・公開後チェック
- ブランチ運用、リリース単位の管理
- 切り戻し手順の用意

**含まない**

- 公開するコンテンツの内容決定 → 企画組織／設計組織
- 不具合の修正 → 実装組織
- Pull Request の作成 → 明示的に依頼された場合のみ行う

## 主な成果物

- 公開手順
- 公開後チェック結果
- リスクメモ（公開により発生しうる影響と、切り戻し方法）

## 他組織との連携

| 区分 | 相手 | 受け渡すもの |
|------|------|-------------|
| 入力元 | 設計 | 公開に影響する構成上の論点 |
| 入力元 | 実装 | 公開対象の成果物 |
| 入力元 | 検証 | 検証結果（公開判断の材料） |
| 出力先 | 統合 | 公開手順、公開後チェック結果、リスクメモ |

## 完了条件

- 公開手順が、そのとおり実行すれば再現できる形で書かれている
- 意図せず公開されるファイルがないか確認済み
- 公開に伴うリスクと切り戻し手順が書かれている
