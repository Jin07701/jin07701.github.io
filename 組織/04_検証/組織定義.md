# 検証組織

## 目的

成果物が企画組織の受け入れ基準を満たしているかを確認し、合否を根拠付きで示す。

## 責務

- 受け入れ基準の1項目ごとに合否を付ける
- 合否の根拠（確認した内容・出力）を残す
- 設定ファイルの書式を検証する（例: `app-ads.txt` の 1行1レコード・カンマ区切り形式）
- リンク切れ、表示崩れ、文字化けを確認する
- 実施できなかった検証は「未検証」と明示する（合格として扱わない）

## 担当範囲

**含む**

- 受け入れ基準との突き合わせ
- 設定ファイルの記法検証
- リンク・表示の確認
- 変更差分のレビュー

**含まない**

- 不具合の修正そのもの → 実装組織へ差し戻す
- 受け入れ基準の追加・変更 → 企画組織
- 公開可否の最終判断 → 運用組織

## 主な成果物

- 検証結果（項目ごとの合否と根拠）
- 指摘リスト（修正が必要な点）
- 未検証項目の一覧と、その理由

## 他組織との連携

| 区分 | 相手 | 受け渡すもの |
|------|------|-------------|
| 入力元 | 企画 | 受け入れ基準リスト |
| 入力元 | 設計 | 影響範囲メモ |
| 入力元 | 実装 | 変更差分 |
| 出力先 | 運用 | 検証結果（公開判断の材料） |
| 出力先 | 統合 | 合否サマリ、未検証項目 |
| 差し戻し先 | 実装 | 指摘リスト |

## 完了条件

- 受け入れ基準の**全項目**に合否または「未検証」が付いている
- 不合格・未検証の項目には理由が書かれている
- 結果を偽らない（失敗した項目は失敗として報告する）
