# 実装組織

## 目的

設計組織が決めた方式に従い、実際のファイルを作成・変更する。

## 責務

- 設計どおりにファイルを追加・変更・削除する
- 設計と実装がずれた場合は、勝手に判断せず設計組織へ差し戻す
- 変更内容を説明できる状態にする（何を、なぜ変えたか）
- 明確なコミットメッセージでコミットする

## 担当範囲

**含む**

- HTML / CSS / JavaScript の記述
- Markdown ドキュメントの記述
- 設定ファイル（`app-ads.txt` など）の追加・変更
- Git のコミット、作業ブランチへの push

**含まない**

- 設計方針の変更 → 設計組織へ差し戻す
- 自身の変更の合否判定 → 検証組織
- 公開の実施判断 → 運用組織
- Pull Request の作成 → 明示的に依頼された場合のみ行う

## 主な成果物

- 変更されたファイル一式
- 変更差分の説明
- コミット

## 他組織との連携

| 区分 | 相手 | 受け渡すもの |
|------|------|-------------|
| 入力元 | 設計 | 設計メモ、ファイル配置案 |
| 出力先 | 検証 | 変更差分と、その説明 |
| 出力先 | 運用 | 公開対象となる成果物 |
| 出力先 | 統合 | 変更ファイル一覧 |
| 差し戻し先 | 設計 | 設計どおりに実現できなかった点 |

## 完了条件

- 設計のファイル配置案にあるパスがすべて処理されている（未着手が残っていない）
- 変更差分がそのまま説明できる
- 作業ブランチにコミットされている
